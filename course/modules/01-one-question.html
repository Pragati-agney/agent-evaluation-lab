One Question, End to End

What this project does, and what really happens when you ask its AI a question

An AI assistant, plus a strict exam for it

This project has two halves. One half is an AI agent that answers engineering questions, like "What revision is part B-104 on?" The other half is an exam that grades every answer the agent gives.

The exam is the real star. Anyone can wire up a chatbot. Knowing for certain it still works after every change is the hard part.

🤖
The agent

Reads a question, decides who should handle it, looks up data, writes an answer

📝
The graders

Six checks that score every answer: some are simple rules, two are AI judges

🚧
The gatekeeper

Blocks any code change from going live if a single grade drops

Think of a parcel sorting depot

When a parcel arrives at a depot, a sorter reads the label and sends it down the right conveyor belt. Nobody opens every parcel; one person decides where it goes, then a specialist handles it.

Your question is the parcel. A supervisor reads it and sends it to one of four belts:

📐

cad_agent

Change shapes and sizes: "make bracket A 3 mm thick"

🌡️

simulation_agent

Run tests on a design: "run a stress simulation"

🗂️

plm_agent

Look up a part's history: "what revision is B-104 on?"

❓

clarify

Too vague to sort: "check bracket A." Ask for more detail

🔎
Only one belt is "real" today

The CAD, simulation and clarify specialists are placeholders that reply with a fixed sentence. The PLM agent is the only one that actually looks data up, so that's the one we'll follow.

The sorter's decision, in real code

Here's the exact code that reads the supervisor's choice and picks the next box. It's the "which conveyor belt?" moment from app/graph.py.

CODE 
def route_after_supervisor(
    state: AgentState,
) -> str:

    decision = state["routing_decision"]

    if decision is None:
        return "clarify"

    return decision.route
PLAIN ENGLISH

Define a function called "route after supervisor"...

...that receives the agent's state (its shared notepad)...

...and hands back a piece of text: the name of the next box.

 

Read the supervisor's decision off the notepad.

 

If there's no decision at all (it's empty, which Python calls None)...

...play it safe and send the question to "clarify".

 

Otherwise, go wherever the supervisor said: for our question, "plm_agent".

💡
Always have a safe default

Notice the fallback: if the decision is missing, the question goes to "clarify" instead of being sent somewhere random. Engineers call this failing safe. It only covers a missing decision, though. If the AI service itself is down, that call errors out before this code runs. When you ask AI to build routing logic, ask: "what happens if the decision is missing, and what happens if the AI call fails?"

Why grade an AI at all?

Normal code is predictable: same input, same output, every time. An LLM isn't. Tweak one sentence of its instructions and it might start sending stress questions to the CAD agent.
