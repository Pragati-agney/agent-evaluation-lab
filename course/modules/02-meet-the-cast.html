The supervisor fills in a form, not a letter

Picture a hospital triage nurse. They don't write the doctor an essay; they tick one box on an intake form: cardiology, orthopaedics, or "needs more info." A tick box can't be misread.

The supervisor works the same way. Instead of free text, the AI must return a structured output that matches this form from app/models.py:

CODE 
class RoutingDecision(BaseModel):
    route: Literal[
        "cad_agent",
        "simulation_agent",
        "plm_agent",
        "clarify",
    ]

    reason: str
PLAIN ENGLISH

Define a form called "RoutingDecision", built on Pydantic's form template (a class).

Field one, "route", must be exactly one of these choices (Literal):

the CAD specialist,

the simulation specialist,

the PLM specialist,

or "ask the user for more detail."

End of the allowed choices.

 

Field two, "reason": a short free-text explanation of the choice (a string).

💡
Forms are what make grading possible

Because the route is always one of four exact words, a grader can check it with a simple "does it equal plm_agent?" That's impossible with an essay. When you want to test an AI feature, first ask your AI tool to make its output structured.

The tool: how the agent touches real data

An LLM only knows what it was trained on; it has no idea what revision B-104 is on today. A tool is a function the AI is allowed to call to look things up. Here's the one in app/tools.py:

CODE 
@tool
def get_part_metadata(part_id: str) -> dict:
    """Get PLM metadata for an engineering part.

    Use this tool when information about a part's revision,
    lifecycle state, or version is required.
    """

    # Fake enterprise system for our lab.
    # Later this could be Teamcenter, a REST API,
    # database, connector, etc.
    return {
        "part_id": part_id,
        "revision": "C",
        "lifecycle_state": "Released",
        "version": "3.2",
    }
PLAIN ENGLISH

Mark the next function as a tool the AI may call (this "@" line is a decorator).

The tool takes a part ID (text) and returns a dictionary of facts.

This description (a docstring) is read by the AI...

 

...to decide when this tool is worth calling: revisions,

lifecycle states, or versions.

End of the description.

 

A note for humans (a comment): this is fake data for the lab...

...in real life this would call a PLM system like Teamcenter or a REST API.

 

Hand back the facts:

the part ID that was asked about,

revision C (always, in this lab),

approval state "Released",

version 3.2.

The tool loop

After every reply, the graph checks: "did the PLM agent ask for a tool?" If yes, run the tool and loop back. If no, stop. This loop pattern is called ReAct (reason, then act), and it's how most tool-using agents work.
